# Building the GitHub Pages website

This project generates static HTML, CSS and JavaScript for the academic website. It writes `../docs/` and mirrors those generated files to the repository root, which is the existing GitHub Pages publishing source.

## Requirements

- Node.js 22.13 or newer and npm.
- Python 3, using only its standard library for ZIP creation and validation.

## Get the source on your laptop

Clone the complete repository so that source edits remain connected to GitHub:

```bash
git clone https://github.com/rotich4499/rotich4499.github.io.git
cd rotich4499.github.io
cd github-pages
```

Run the following from the `github-pages` directory:

```bash
npm install
npm run build
npm run check
```

`npm run build` compiles the Markdown lessons and download package, renders all personal and learning pages, and writes the static assets, custom error page, sitemap and `.nojekyll` marker.

`npm run check` checks every page and local link, lesson section links, file and ZIP checksums, the CV download, the code-copy interaction, and exclusion of the full bachelor’s report.

## View the website locally

After building, return to the repository root and start a static server:

```bash
cd ..
python3 -m http.server 8000 --bind 127.0.0.1
```

Open **http://127.0.0.1:8000/** in your browser. Leave that terminal open while viewing; stop the server with Ctrl+C. Use another terminal for edits and rebuilding. No ChatGPT or Sites login is needed to run this static website locally.

## Editing

- Personal pages: `src/app/`.
- Shared navigation and layout: `src/components/profile-layout.tsx`.
- Learning layout and styles: `src/app/learn/`.
- Lesson Markdown and calculation files: `learning-source/`.
- Photo, favicon and CV: `src/public/`.
- Research presentation PDFs and their source checksums: `src/public/presentations/`.
- Original plots extracted from the presentations: `src/public/images/research/`; figure captions and source-slide links are generated by `src/components/research-evidence.tsx`.
- Static browser interactions: `scripts/browser.js`.

For example, edit `src/app/page.tsx` to change the homepage, `src/app/projects/diamond/page.tsx` for the diamond study, or `src/app/globals.css` for the personal-page styling. Run `npm run build` again from this directory and refresh the browser to see your edits. If you add a page, also register its route in `src/render.tsx` and update the expected route count in `scripts/check_static.py`.

## Pull, edit and publish

From the repository root, first download changes made elsewhere while your working tree is clean:

```bash
git pull --ff-only origin main
```

Make your source edits, then build and check from `github-pages`:

```bash
cd github-pages
npm run build
npm run check
cd ..
git status
git add -A
git commit -m "Update my website"
git push origin main
```

Review `git status` before staging. Include the editable source, generated root files and `docs/` mirror in the same commit. Keep local secrets and unrelated personal files outside this public repository.

`git pull` downloads remote changes; `git push` uploads your commits. The existing GitHub Pages configuration publishes the generated website from `main` at the repository root. Check the repository’s **Actions** tab for deployment completion after pushing. Editing source alone does not update the published HTML until you build and commit the generated files.

If changes were made on GitHub after you started editing, commit your local work, run `git pull --rebase origin main`, resolve any source conflicts, rebuild and check, then commit any regenerated output and push. Never force-push to resolve a normal editing conflict.

GitHub requires your own account authentication to push. Use your normal GitHub authentication method; it is not necessary for cloning this public repository.

The canonical learning repository is [computational-materials-learning](https://github.com/rotich4499/computational-materials-learning). Keep this project’s `learning-source/` copy aligned with it when lessons or scientific files change. Generated lesson JSON and download folders are rebuilt from that source.

Build and check after editing, then commit the source, generated root files and `../docs/` output together. `published-files.json` records which root files belong to the generated site; existing source files are preserved. Keep the bachelor’s report excluded from both source assets and published files.
